# Tujuan

Buat atau perbarui file `README.md` di root repositori agar menjadi dokumentasi proyek yang profesional, informatif, sistematis, dan mudah dipahami.

README harus menjelaskan identitas proyek, tujuan aplikasi, fitur, teknologi, serta kelebihan proyek berdasarkan kondisi implementasi yang sebenarnya.

# Alur Kerja

1. **Investigasi proyek terlebih dahulu.**
   - Baca dokumentasi dan konfigurasi proyek yang sudah tersedia.
   - Periksa struktur direktori proyek.
   - Periksa file `pubspec.yaml` dan dependensi yang digunakan.
   - Periksa file entrypoint aplikasi.
   - Periksa implementasi fitur-fitur utama di dalam direktori `lib/`.
   - Periksa konfigurasi lain yang relevan untuk memahami cara kerja dan kemampuan aplikasi.

2. **Pahami kondisi proyek.**
   - Identifikasi tujuan utama aplikasi.
   - Identifikasi fitur yang sudah diimplementasikan.
   - Identifikasi teknologi dan dependensi yang benar-benar digunakan.
   - Pahami fungsi dan kegunaan setiap fitur utama.
   - Identifikasi kelebihan proyek berdasarkan implementasi, arsitektur, dan kemampuan yang benar-benar tersedia.

3. **Susun README.md.**
   - Gunakan hasil investigasi sebagai dasar penulisan.
   - Susun informasi secara sistematis dan profesional.
   - Pastikan setiap informasi sesuai dengan kondisi proyek saat ini.
   - Jelaskan kelebihan proyek berdasarkan fakta yang ditemukan, bukan berdasarkan asumsi.

4. **Periksa hasil dokumentasi.**
   - Pastikan tidak ada informasi yang dikarang.
   - Pastikan seluruh fitur yang dicantumkan benar-benar tersedia.
   - Pastikan penjelasan sesuai dengan implementasi proyek.
   - Pastikan dokumentasi mudah dibaca dan tidak mengandung pengulangan yang tidak diperlukan.

# Ketentuan Penulisan

1. **Bahasa:** Seluruh isi README wajib menggunakan bahasa Indonesia yang formal, baku, dan sesuai kaidah bahasa Indonesia.
2. **Keakuratan informasi:** Seluruh informasi yang ditulis wajib memiliki dasar yang dapat ditemukan dan diverifikasi di dalam proyek.
3. **Fitur:** Cantumkan fitur yang benar-benar sudah diimplementasikan beserta penjelasan fungsi dan kegunaannya.
4. **Kelebihan proyek:** Jelaskan kelebihan dan nilai tambah proyek berdasarkan kemampuan, fitur, teknologi, atau implementasi yang benar-benar ditemukan.
5. **Teknologi:** Cantumkan framework, bahasa pemrograman, dependensi, dan teknologi lain yang memang digunakan.
6. **Struktur:** Gunakan heading, subheading, daftar, tabel, dan blok kode jika diperlukan agar dokumentasi mudah dipahami.
7. **Kejelasan:** Gunakan penjelasan yang ringkas, jelas, dan tidak berulang.
8. **Kesesuaian:** Bedakan fitur yang sudah tersedia dengan fitur yang masih dalam pengembangan jika keduanya ditemukan.

# Larangan

1. Dilarang mengarang fitur, kelebihan, teknologi, kemampuan, atau informasi lain mengenai proyek.
2. Dilarang mencantumkan informasi yang tidak dapat diverifikasi dari isi repositori.
3. Dilarang menyatakan fitur sudah tersedia apabila implementasinya belum ditemukan.
4. Dilarang mengubah, menghapus, atau menambahkan kode Dart.
5. Dilarang melakukan refactoring atau perbaikan implementasi aplikasi.
6. Dilarang mengubah konfigurasi proyek atau menambahkan dependensi untuk keperluan penulisan README.

# Batasan Ruang Lingkup

1. Pekerjaan hanya mencakup investigasi proyek dan pembuatan atau pembaruan file `README.md` di root repositori.
2. Pemeriksaan kode hanya dilakukan untuk memahami fitur, arsitektur, dan kemampuan proyek.
3. Jangan mengubah file kode Dart selama proses investigasi maupun penulisan dokumentasi.
4. Jangan mengubah file lain di luar `README.md`.
5. Jika informasi tertentu tidak dapat ditemukan atau diverifikasi, jangan membuat asumsi untuk melengkapinya.

# Hasil Akhir

Setelah selesai:

1. Pastikan `README.md` sudah tersusun secara profesional dan sistematis.
2. Pastikan seluruh informasi sesuai dengan kondisi proyek yang sebenarnya.
3. Pastikan kelebihan proyek dijelaskan berdasarkan implementasi nyata.
4. Pastikan tidak ada kode Dart atau file proyek lain yang berubah.
5. Laporkan bahwa README berhasil dibuat atau diperbarui.
